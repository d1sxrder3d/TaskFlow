# TaskFlow Pro

TaskFlow Pro — архивный pet-проект для управления задачами, проектами, организациями, тегами и файлами.

## Статус проекта

Проект **не завершён** и в текущем виде рассматривается как архивный/legacy-код.

Дальнейшая активная разработка **не планируется**. Репозиторий сохранён как пример архитектуры, набора сущностей и попытки собрать полноценный task/project management backend.

## Что в проекте уже есть

- REST API на `FastAPI`
- асинхронная работа с БД через `SQLAlchemy`
- миграции через `Alembic`
- JWT-аутентификация с access/refresh token’ами
- хранение refresh token’ов в БД и их отзыв при logout
- сущности для:
  - пользователей
  - организаций
  - проектов
  - задач
  - тегов
  - файлов
- связи между сущностями:
  - пользователь ↔ организация
  - пользователь ↔ проект
  - пользователь ↔ задача
  - задача ↔ тег
- отдельные слои `models / repositories / services / routers`
- тесты для API, репозиториев, сервисов и core-утилит
- Dockerfile и базовая конфигурация окружения

## Что демонстрирует этот репозиторий

Несмотря на незавершённость, у проекта есть несколько сильных сторон:

1. **Хорошо выделенная архитектура**
   - логика разделена по слоям
   - есть DI через зависимости FastAPI
   - репозитории отделены от сервисов и роутеров

2. **Неплохая предметная модель**
   - проект уже отражает реальную командную работу
   - предусмотрены организации, роли, проекты, задачи и теги
   - заложены связи между участниками и объектами

3. **Продуманная auth-модель**
   - access/refresh token flow
   - хранение refresh token’ов в БД
   - возможность отзывать сессии
   - учёт IP и user-agent

4. **Асинхронный стек**
   - современный backend-стек для производительной веб-API
   - async SQLAlchemy + FastAPI + Alembic

5. **Покрытие тестами**
   - есть тесты на разные уровни
   - видно, что проект не просто набросок, а реальная попытка довести backend до рабочего состояния

## Что было задумано, но не доведено до конца

- полноценная система ролей и прав доступа
- управление участниками организаций и проектов на уровне бизнес-логики
- развитая файловая подсистема с реальной загрузкой и обработкой
- richer response-схемы с вложенными связями
- более строгая и унифицированная схема API и Pydantic-моделей
- production-ready конфигурация секретов, ключей и окружения

## Важно

В проекте могут встречаться незавершённые места, технический долг и отдельные несоответствия между слоями. Это ожидаемо для старого, остановленного проекта.

Если использовать этот репозиторий дальше, его лучше воспринимать как основу для нового backend-проекта, а не как полностью готовый продукт.
